01 · сигналы, а не VDOM
Граф — сразу.
DOM — в кадре.
set() сразу помечает зависимые узлы грязными. DOM никто не трогает до следующего тика rAF.
const [count, setCount] = createSignal(0)const label = createMemo(() => `${count()} unread`) createMutationEffect( () => label(), // compute · чисто (v) => el.textContent = v // apply · в кадре)
02 · один проход на кадр
Три записи.
Один коммит.
Записи копятся между тиками. На тике граф досчитывается один раз, и каждый DOM-биндинг применяется один раз, по порядку.
setCount(1)setCount(2)setCount(3) // граф: count → label, пересчитан один раз// DOM: el.textContent = "3 unread", один раз
03 · measure → mutate
Сначала чтение.
Потом запись.
Эффекты приходят в любом порядке. Планировщик выполняет все чтения layout до первой записи в DOM, поэтому layout считается один раз за кадр, без thrashing.
createMeasureEffect( () => messages(), // зависимости () => setHeight(list.scrollHeight) // чтение layout)createMutationEffect( () => height(), (h) => spacer.style.height = h // запись в DOM)
04 · forced reflow
Читать после записи?
Скажи явно.
Forced reflow — явный слот измерения после mutate со своим слотом записи следом. Один лишний layout, осознанно, всё ещё до paint. Редкость by design.
createMutationEffect(() => older(), (m) => list.prepend(...m)) // 1 · записьcreateEffect(() => older(), () => setTop(anchor.offsetTop), // 2 · чтение в кадре frameForcedReflow)createMutationEffect(() => top(), (t) => list.scrollTop += t) // 3 · запись после

Сначала анимация.
Обновления потом.
Пока идёт blocking-анимация, кадровая работа ждёт — целыми кадрами, не половинами. Когда она кончается, всё приземляется одним проходом.
