# frameact client-readiness kit — Implementation Plan (plan 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build what a Telegram Web A–class client needs before its main screens (audit `.superpowers/client-readiness-audit.md` §3.1 items 2–7, roadmap "6A"): the small primitives (`onMount`, `onDestroy`, `previous`/`currentOrPrev`/`frozenWhile`, `watchHeavyAnimation`, `lazy`, `splitProps`, `debounce`/`fastRaf`/`throttleWithTickEnd` exports), extra-styles parity with string `style=`, a Vite lint against destructured props, `createShowTransition`/`<ShowTransition>`/`createMediaTransition`, `<Transition>` with keep-alive slides and a heavy-animation scope per subtree, `createScrollAnchor`/`<InfiniteScroll>` with phase-correct scroll anchoring, a regression test for R1 (the store-gate release must not split a frame — fixed on the base by cb83c4c), and the porting guide (hooks → primitives, the store-B state model, identity pitfalls).

**Architecture:** Everything is built on the existing public surface — two-phase effects on the three frame queues, `For order="manual"`, token-diff classes, the store gate — with no new dependencies and no changes to the core's data structures. Components are hand-written `.ts` calling the runtime the compiler targets (`createComponent`, `insert`, `spread`, `For`) so that `frameact/kit` works for a consumer whose Vite plugin excludes `node_modules`. Phase discipline throughout: layout is read in measure effects, `onMount`, event handlers (`animationend`, `scroll`) and forced-reflow effects; DOM is written in mutation effects and `requestMutation` tasks; a measure→mutate hand-off goes through a signal, so the write lands in the same frame and is gated like any other binding. The new UI layer is a separate package entry `frameact/kit`; the generic primitives go into `frameact` and `frameact/dom` (scope decision 1).

**Tech Stack:** TypeScript 7 (strict), pnpm, Vite 8 + vitest 5 + jsdom 30, oxlint. No new dependencies.

**Brief and sources:** `.superpowers/plan6-context.md` (main checkout `/Users/denisurevic/Documents/frameact`); the audit `.superpowers/client-readiness-audit.md` (§1.3–1.7, §3.1 items 2–7, §3.4, §4 R1/R2, §5); spec `docs/superpowers/specs/2026-10-11-frameact-design.md` §3.2 (effects, frame queues, heavyAnimation scopes), §3.3 (dom), §3.5 (store), §4 (structure, `examples/`), §5; telegram-tt behaviour reference (observed behaviour and public interfaces only; no code from it is ported into frameact): `Transition`, `ShowTransition`, `InfiniteScroll`, `useShowTransition`, `useMediaTransition`, `usePrevious`, `useCurrentOrPrev`, `useFrozenProps`, `useHeavyAnimation`, `useModuleLoader`, the scheduler utilities, the CSS animation-end listeners and teact's `updateStyle`/`setExtraStyles`. The pre-flight also fixed, against the first draft: Task 3 no longer reverts the base's own-keys hardening of `styles.ts`; `<ShowTransition>` no longer remounts on `isHidden` and its DEV check no longer evaluates the children getter; `<Transition>` restores the height after a switch without animation, does nothing after dispose, and `waitForAnimationEnd`'s cancel clears the post-event delay; scroll anchoring and `<InfiniteScroll>` see in-place writes to a store array (`produce`/`reconcile`).

1. **Export decision: `frameact/kit`, not `examples/`.** Spec §4's `examples/` is a demo app (chat list + message list, "both patterns of §3.5"); the audit's items are library code the client imports from every screen (`<Transition>` appears in 79 tt component files, `useShowTransition` in 47, `<InfiniteScroll>` in 32) and plan 5's benchmark app is to be built on it ("мини-tweb на ките"). A demo cannot be a dependency, so the kit is a package entry: `"./kit": "./src/kit/index.ts"` + tsconfig path + vitest alias (Task 5). The split: **UI components that carry CSS class contracts** (tt's `Transition.scss`, `.opacity-transition`, `.ListItem`) → `frameact/kit` (`Transition`, `ShowTransition`, `createShowTransition`, `createMediaTransition`, `InfiniteScroll`, `createScrollAnchor`, `waitForAnimationEnd`/`waitForTransitionEnd`); **generic reactive primitives** → `frameact` (`onMount`, `onDestroy`, `watchHeavyAnimation`, `previous`, `currentOrPrev`, `frozenWhile`); **component-level DOM helpers** → `frameact/dom` next to `mergeProps`/`Show` (`splitProps`, `lazy`); **scheduler utilities** → `frameact/scheduler` only (`debounce`, `fastRaf`, `throttleWithTickEnd`), because `test/index.test.ts` (I6) pins that scheduler-level names like `throttle` stay out of the main entry. `examples/` stays for plan 5's demo. The kit ships **no CSS**: the client brings tt's stylesheets; the class names are the contract (documented per component).
2. **Kit components are plain `.ts`** (`createComponent(For, …)`, `insert`, `spread`), like `src/dom/flow.ts`: a consumer's `frameact()` Vite plugin excludes `node_modules` by default, so `.tsx` inside the package would never be compiled. Tests build props by hand (`get activeKey() { return key(); }`), exactly as the compiler emits them.
3. **`onMount` / `onDestroy` (user decision).** `onMount(fn)` = a measure effect with no dependencies (`fn` runs inside the apply half, untracked, once, after attach, in the measure phase); a returned cleanup is registered on the owner that called `onMount` through `scoped(() => onDispose(cleanup), owner)` (apply halves have no owner). `onDestroy(fn)` = `onDispose(fn)` plus a DEV warning when the current owner is a re-running computation (`_effect` or `_compute !== null` — a memo or an effect compute, where `onCleanup` is the right tool) and when there is no owner. Like `onCleanup`, it runs **synchronously at dispose, in whatever phase**; the core defers only *apply-cleanups of DOM-writing effects* to the mutate phase (`setApplyCleanupDisposer` in `frame.ts`), and `onDestroy` is not one of those, so a live-DOM write outside the component's own subtree (e.g. `document.body.classList`) must be wrapped in `requestMutation` — documented in the JSDoc and the guide (§2.7).
4. **`previous`/`currentOrPrev`/`frozenWhile` are memos and therefore lazy.** A memo nobody reads between two changes does not see the intermediate value; `currentOrPrev` reads its inner `previous` on every pass for this reason (found by the test: reading it only in the `else` branch made its first computation happen after the gap). Documented in the JSDoc and the guide; `<Transition>` therefore tracks its previous key eagerly in an effect, not with `previous`.
5. **Extra-styles parity:** a per-element registry (`WeakMap<Element, Map<string, value>>` — a `Map`, and own keys only, keeping the base's prototype-pollution hardening of `styles.ts`: `Object.keys`/`Object.hasOwn`, never `for…in`) that **accumulates** across `setExtraStyles` calls (teact replaces it per call; `Transition` sets `transition` and `height` in separate calls and needs both) and is re-applied after every `cssText` write (`style(el, string)`, and the `cssText = ''` of `null`/string→object transitions). `null`/`undefined` removes from the registry. The object form is unchanged (per-property diff; keep bound and imperative properties disjoint).
6. **Destructured-props lint = a regex scan** next to the existing two lints in `src/vite/index.ts`: `function Name({`, `const|let|var Name[: T] = ({` / `= function ({` for a capitalised `Name`, and `const { … } = props` in a body. Known false positives: a capitalised helper taking an object (the message says "if X is not a component, ignore"), and the body form inside a memo/effect compute (tracked there, so harmless); known false negative: a type annotation containing `=`/`=>` (`const X: (p: P) => Node = ({`). Dev only, with Rollup positions.
7. **`<Transition>` semantics** follow tt where cheap and differ in four stated ways. Same: classes (`Transition`, `Transition-${name}`, `Transition-${name}Backwards`, `Transition_slide`, `-active/-from/-to/-inactive`), `direction` (`auto`/`inverse`/`1`/`-1`), the previous slide kept alive across and after the animation, `renderCount` (= keep every visited key; slides in key order), `shouldCleanup`/`cleanupExceptionKey`/`cleanupOnlyKey`, `shouldRestoreHeight`/`restoreHeightKey`/`contentSelector`, `onStart`/`onStop`, `isBlockingAnimation`, the watched slide (`from` for `reveal`/`slideFadeAndroid` backwards, else `to`), the 1 s `animationend` fallback, the superseded-step rule (an older step's end only releases its heavy animation). Different: (a) **a scope per subtree** — the animation runs on `props.scope ?? createHeavyAnimationScope()` (a child of the enclosing scope), which is *provided* to the slides (their effects park under a blocking animation) but **not** to the transition's own effects (a new `activeKey` during an animation supersedes it at once instead of being parked by it; tt freezes everything); (b) `disableAnimation` is a plain prop (tt reads `selectCanAnimateInterface(global)` and a `DISABLEABLE_ANIMATIONS` set — client policy); (c) `restoreHeight` follows the *settled* key (set when a step's animation ends, or at once for a switch without animation) and measures it in the **forced-reflow** phase, after the mutate phase that created and attached the slide, writing the container height in that phase's mutate step — the same frame (tt reads `clientHeight` at `animationend` event time and re-measures in a `useEffect` on every render; a measure-phase effect would run before a new key's slide exists, so a switch with `disableAnimation`/`name="none"` would keep the old height); (d) slides are **always wrapped** in a `div.Transition_slide` and `children` is JSX (created once per slide) or `(slide: { key, isActive, isFrom, activeKey }) => JSX` called once per slide. Not ported (follow-ups): `slideOptimized`/`slideOptimizedRtl` (transform + `transitionend` variant: 3 files in tt), `withSwipeControl` (3), `nextKey` (0), `shouldWrap`/`wrapExceptionKey`. The slide list is created inside a tiny `Slides` component that provides the scope: creating it inside the `HeavyAnimationScope` component's `children()` memo made the `For` owned by that memo and recreated on every change (found by the tests).
8. **Scroll anchoring** is three effects on one `items` accessor (a store array is tracked by its **shape** — `trackItems` reads `[$TRACK]`, which subscribes to the shape and returns a fresh plain array per change — because model B's `produce`/`reconcile` rewrite the array in place and its identity never changes): measure (snapshot: the anchor item — the previous anchor if still listed, else the first item — and its `getBoundingClientRect().top`), forced reflow (the anchor's new top → `delta` → a `{ top }` signal), mutation (`el.scrollTop = top`, which lands in the forced-reflow mutate phase of the **same** frame — `frame.ts` runs mutate work produced by reflow applies there). `<InfiniteScroll>` adds tt's scroll handler (anchor tracking on scroll, `isNearTop`/`isNearBottom` by `sensitiveArea`, `onLoadMore` debounced `1000, true, false`, re-armed per `items` change), the initial preload (list shorter than `preloadBackwards`, or not filling the viewport), and ignores the one scroll event a restore causes. Not ported: `withAbsolutePositioning`/`maxHeight`, `cacheBuster`, `beforeChildren` (put it in `children`), `useInfiniteScroll` (the viewport-id window: pure functions, a follow-up).
9. **R1 is already fixed on the base** (cb83c4c, part of the store fix round fa66103..063af48): `release` in `src/store/gate.ts` re-books the parked set inside `releaseInFrame` (`src/core/frame.ts`: a `requestMeasure` task that drains the measure queue inline, like `releaseParked`), so a release from the mutate phase no longer splits measure and mutate halves across frames. cb83c4c's tests cover the end from a raw `requestMutation` task and from a timer; **Task 7 adds the remaining case** — `end()` called from inside a mutation apply (an applier) — to `test/store/gate.test.ts`; Task 8's integration test (scroll anchor + list under a store-gated animation ended from a mutate task) depends on the same fix. No change to the store or the core in this plan.
10. **stricterdom (plan 4) is not built or imported.** Where the client will need `forceMeasure`/`forceMutation`/`suppressStrict`, the guide names them as plan 4's `frameact/stricterdom` surface; the kit itself needs none of them (every read/write is already in its phase). `flushSync`'s production contract (R3) and `onStoreWrite` (cache/multitab) are follow-ups.
11. **`lazy` without Suspense:** `lazy(loader, { placeholder? })` returns a component with `preload()`; the module is cached per `lazy` call; a rejected load is reported through the owner's `onError` handlers (else the console), the placeholder stays, the promise cache is cleared so the next instance retries. `splitProps` is Solid's without the Proxy branch (keys as of the call).

import {
  createEffect, createHeavyAnimationScope, createMemo, createMutationEffect, createRoot, createSignal, getPhase,
  onCleanup, onDestroy, onMount, provideHeavyAnimationScope, watchHeavyAnimation,
} from '../../src/index';
import { createComponent } from '../../src/dom/component';
import { insert } from '../../src/dom/insert';
import { container, useDomHarness } from '../helpers/dom';
import { flushMicrotasks } from '../helpers/micro';

const { frame } = useDomHarness();

describe('onMount', () => {
  it('runs once, after attach, in the measure phase; it sees real layout and does not re-run on signal changes', async () => {
    const root = container();
    const [n, setN] = createSignal(0);
    const log: string[] = [];
    const Comp = () => {
      const el = document.createElement('div');
      onMount(() => {
        log.push(`${getPhase()}:${el.isConnected}:${n()}`);
      });
      insert(el, () => String(n()));
      return el;
    };
    createRoot(() => insert(root, createComponent(Comp, {})));
    expect(log).toEqual([]); // not synchronous: the nodes are detached at creation
    await frame();
    expect(log).toEqual(['measure:true:0']);
    setN(1);
    await frame();
    expect(log).toEqual(['measure:true:0']); // untracked: the read of n() inside did not subscribe
  });

  it('a returned cleanup runs on dispose, in owner cleanup order with onCleanup; it never runs if the owner dies before mount', async () => {
    const log: string[] = [];
    const dispose = createRoot((d) => {
      onCleanup(() => log.push('cleanup-1'));
      onMount(() => () => log.push('mount-cleanup'));
      onCleanup(() => log.push('cleanup-2'));
      return d;
    });
    await frame();
    expect(log).toEqual([]);
    dispose();
    // the mount cleanup was registered at mount time (after both onCleanup calls), so it runs after them (LIFO)
    expect(log).toEqual(['mount-cleanup', 'cleanup-2', 'cleanup-1']);

    const early: string[] = [];
    const disposeEarly = createRoot((d) => {
      onMount(() => {
        early.push('mounted');
        return () => early.push('cleanup');
      });
      return d;
    });
    disposeEarly(); // before the first frame: the measure effect is disposed with its owner
    await frame();
    expect(early).toEqual([]);
  });
});

describe('onDestroy', () => {
  it('runs once when the component is disposed (not on signal changes); DEV warns inside an effect or memo compute', async () => {
    const warn = vi.spyOn(console, 'warn').mockImplementation(() => {});
    const [n, setN] = createSignal(0);
    const log: string[] = [];
    const Comp = () => {
      onDestroy(() => log.push('destroy'));
      createEffect(() => n(), () => {});
      return null;
    };
    const dispose = createRoot((d) => {
      createComponent(Comp, {});
      return d;
    });
    setN(1);
    await flushMicrotasks();
    expect(log).toEqual([]);
    expect(warn).not.toHaveBeenCalled();
    dispose();
    expect(log).toEqual(['destroy']);

    createRoot(() => {
      createMemo(() => {
        onDestroy(() => {});
        return 1;
      })();
      createMutationEffect(() => {
        onDestroy(() => {});
        return 1;
      }, () => {});
    });
    expect(warn).toHaveBeenCalledTimes(2);
    expect(String(warn.mock.calls[0][0])).toContain('onCleanup');
    warn.mockClear();
    onDestroy(() => {}); // no owner
    expect(warn).toHaveBeenCalledTimes(1);
    expect(String(warn.mock.calls[0][0])).toContain('no owner');
  });
});

  it('listens on the owner\'s scope by default, fires onStart at once if animating, and unsubscribes on dispose', () => {
    const scope = createHeavyAnimationScope();
    const log: string[] = [];
    const end1 = scope.begin(Infinity);

      return d;

    expect(log).toEqual(['start', 'end', 'start']);

import { createEffect, createRoot, createSignal, currentOrPrev, flushSync, frozenWhile, previous } from '../../src/index';

/** Read `get` from an effect so every change is observed; returns the log. */
function observe<T>(get: () => T): T[] {
  const log: T[] = [];
  createRoot(() => createEffect(() => get(), (v) => { log.push(v); }));
  flushSync();
  return log;
}

describe('previous', () => {
  it('is undefined until the first change, then the value before the current one; same value is not a step', () => {
    const [n, setN] = createSignal(1);
    const log = observe(previous(n));
    expect(log).toEqual([undefined]);
    setN(2);
    flushSync();

// Component lifecycle helpers over the owner tree (plan 6, client-readiness kit): the two moments
// a teact component cares about — "my nodes are attached" (`useEffect(fn, [])`) and "I am gone"
// (the unmount cleanup) — plus the heavy-animation listener that unsubscribes with its owner.
import { DEV } from '../env';
import { getScope, onDispose, scoped } from './core';
import { createMeasureEffect } from './frame';
import type { Computation, Scope } from './types';
import { currentHeavyAnimationScope, onHeavyAnimation, type HeavyAnimationScope } from '../scheduler/heavyAnimation';

/** True for an owner whose body re-runs (a memo or an effect compute); false for a component/root scope. */
function isComputation(owner: Scope): boolean {
  const c = owner as Computation;
  return c._effect === true || c._compute !== null;
}

/**
 * Run `fn` once, after the owner's nodes are attached, in the **measure phase** of the next frame
 * (real layout: `focus()`, `scrollTop`, `getBoundingClientRect` are fine; stricterdom-safe). Never
 * re-runs: it is a measure effect with no dependencies (`fn` runs untracked, inside the apply half).
 * `fn` may return a cleanup, registered on the owner that called `onMount` (it runs on dispose; a
 * DOM write in it goes through `requestMutation`, see `onDestroy`). Replaces teact's
 * `useEffect(fn, [])` and `useLayoutEffect(fn, [])` for mount-time work.
 */
export function onMount(fn: () => void | (() => void)): void {
  const owner = getScope();
  createMeasureEffect(
    () => undefined,
    () => {
      const cleanup = fn();
      if (typeof cleanup === 'function') {
        if (owner === null) {
          if (DEV) console.warn('[frameact] onMount: the cleanup returned has no owner to run on (onMount was called outside a component).');
          return;
        }
        scoped(() => onDispose(cleanup), owner);
      }
    },
    { name: 'onMount' },
  );
}

/**
 * Run `fn` once, when the owner (the component) is disposed — the component-scope meaning of
 * `onCleanup`. Called from a re-running computation (an effect or memo compute) it would fire on
 * every re-run, which is `onCleanup`'s job: DEV warns and points there. Like `onCleanup`, `fn` runs
 * synchronously at dispose, whatever the phase; the owner's own DOM is detached by its slot's
 * apply-cleanup (deferred to the mutate phase by the core), but a write `fn` makes to the live DOM
 * outside that subtree (`document.body.classList`, a portal target) must be wrapped in
 * `requestMutation(() => …)`.
 */
export function onDestroy(fn: () => void): void {
  const owner = getScope();
  if (DEV) {
    if (owner === null) console.warn('[frameact] onDestroy called with no owner: the callback will never run.');
    else if (isComputation(owner)) {
      console.warn('[frameact] onDestroy inside an effect or memo compute runs on every re-run; use onCleanup there (onDestroy belongs in the component body).');
    }
  }
  onDispose(fn);
}

/**
 * `onHeavyAnimation` bound to the owner: subscribes `onStart`/`onEnd` to `scope` (default: the
 * heavy-animation scope the owner is under, not the root) and unsubscribes when the owner is
 * disposed. `onStart` fires at once if the scope already animates (teact's `useHeavyAnimation`).
 */
export function watchHeavyAnimation(
  onStart?: () => void,
  onEnd?: () => void,
  scope: HeavyAnimationScope = currentHeavyAnimationScope(),
): () => void {
  const off = onHeavyAnimation(onStart, onEnd, scope);
  if (getScope() === null) {
    if (DEV) console.warn('[frameact] watchHeavyAnimation called with no owner: the listener is never removed (use onHeavyAnimation and keep the unsubscribe).');
  } else onDispose(off);
  return off;
}

```ts
// Derived accessors over a source's history (plan 6, client-readiness kit): teact's `usePrevious`,
// `useCurrentOrPrev` and `useFrozenProps` as memos. They observe the source when they are READ:
// a memo is pulled lazily, so a value nobody read between two changes is not a "previous" value.
// Read them from an effect or the JSX (every frame) and they see each change.
import { createMemo, type Accessor } from '../index';

export interface PreviousOptions {
  /** `undefined` does not count as a change: the previous value survives a gap (teact `shouldSkipUndefined`). */
  skipUndefined?: boolean;
}

/**
 * The value `source` had before its current one (`undefined` until the first change). Values are
 * compared with `Object.is`; an unchanged value is not a step.
 */
export function previous<T>(source: Accessor<T>, options?: PreviousOptions): Accessor<T | undefined> {
  const skipUndefined = options?.skipUndefined === true;
  let has = false;
  let last: T | undefined;
  let prev: T | undefined;
  return createMemo(() => {
    const v = source();
    if (has && !Object.is(v, last)) {
      if (!(skipUndefined && v === undefined)) prev = last;
    }
    if (!(skipUndefined && v === undefined) || !has) {
      last = v;
      has = true;
    }
    return prev;
  });
}

export interface CurrentOrPrevOptions extends PreviousOptions {
  /** Always the current value (teact `shouldForceCurrent`): useful when the choice is itself reactive. */
  forceCurrent?: Accessor<boolean>;
}

/**
 * `source()` while it is not `null`/`undefined`, else the last non-empty value — what a closing
 * panel shows while its data is already gone (teact `useCurrentOrPrev`).
 */
export function currentOrPrev<T>(source: Accessor<T>, options?: CurrentOrPrevOptions): Accessor<T | undefined> {
  const prev = previous(source, { skipUndefined: options?.skipUndefined ?? true });
  const force = options?.forceCurrent;
  return createMemo(() => {
    const v = source();
    const p = prev(); // read on every pass: a memo is lazy, and `previous` must see each value to know the steps
    if (force?.() || (v !== null && v !== undefined)) return v;
    return p;
  });
}

/**
 * `source()` while `frozen()` is false; while it is true, the value seen just before the freeze
 * (teact `useFrozenProps`). `alwaysFresh` names keys of an object value that keep updating during
 * the freeze (the result is then a fresh object per change of those keys).
 */
export function frozenWhile<T>(source: Accessor<T>, frozen: Accessor<boolean>, alwaysFresh?: readonly (keyof T & string)[]): Accessor<T> {
  let held: T;
  let holding = false;
  return createMemo(() => {
    const isFrozen = frozen();
    if (!isFrozen) {
      holding = false;
      return source();
    }
    if (!holding) {
      held = source();
      holding = true;
      if (!alwaysFresh?.length) return held;
    }
    if (!alwaysFresh?.length) return held;
    const current = source();
    const out = { ...(held as object) } as T;
    for (const key of alwaysFresh) out[key] = current[key];
    return out;
  });
}
```

```ts
// `lazy` in the spirit of Solid's (packages/solid/src/render/component.ts, MIT, © 2016-2025 Ryan
// Carniato) without Suspense: the component renders `placeholder` (nothing by default) until the
// module arrives, then the loaded component with the same props. Replaces teact's `*.async.tsx`
// + `useModuleLoader` pair (155 files in telegram-tt).
import { DEV } from '../env';
import { handleError } from '../core/core';
import { createMemo, createSignal, getOwner, untrack } from '../index';
import { createComponent, type Component } from './component';

export interface LazyOptions {
  /** Rendered while the module loads (created under the lazy component's owner, disposed when the component arrives). */
  placeholder?: () => unknown;
}

export interface LazyComponent<P> {
  (props: P): unknown;
  /** Start loading now (a hover, an idle moment); the returned promise resolves to the component. */
  preload(): Promise<Component<P>>;
}

/**
 * `lazy(() => import('./Settings'))`: a component that loads its implementation on first render
 * (or `preload()`). The module is cached per `lazy` call; a failed load is reported through the
 * owner's `onError` handlers (else the console), the placeholder stays, and the next instance
 * retries. Heavy first renders during an animation: wrap the instance in `deferUntilIdle`.
 */
export function lazy<P>(loader: () => Promise<{ default: Component<P> }>, options?: LazyOptions): LazyComponent<P> {
  let loaded: Component<P> | undefined;
  let pending: Promise<Component<P>> | undefined;
  const placeholder = options?.placeholder;

  function preload(): Promise<Component<P>> {
    if (loaded) return Promise.resolve(loaded);
    if (!pending) {
      pending = loader().then(
        (m) => {
          loaded = m.default;
          return loaded;
        },
        (error) => {
          pending = undefined; // the next mount retries
          throw error;
        },
      );
    }
    return pending;
  }

  const Lazy = ((props: P) => {
    if (loaded) return createComponent(loaded, props);
    const owner = getOwner();
    const [comp, setComp] = createSignal<Component<P> | undefined>(undefined);
    preload().then(
      (c) => setComp(() => c),
      (error) => {
        try {
          handleError(owner, error);
        } catch (unhandled) {
          console.error('[frameact] lazy: loading the component failed', unhandled);
        }
      },
    );
    return createMemo(() => {
      const C = comp();
      // untracked: the loaded component's own reads must not subscribe this memo
      return C ? untrack(() => createComponent(C, props)) : placeholder ? untrack(placeholder) : undefined;
    });
  }) as LazyComponent<P>;
  Lazy.preload = preload;
  if (DEV) Object.defineProperty(Lazy, 'name', { value: 'Lazy' });
  return Lazy;
}
```

export function splitProps<T extends Record<string, any>, const K extends readonly (readonly (keyof T)[])[]>(
  props: T,
  ...keys: K
): [...{ [I in keyof K]: Pick<T, K[I][number]> }, Omit<T, K[number][number]>] {
  const own = Reflect.ownKeys(props).filter((key) => isOwnProp(props, key)) as (keyof T)[];
  const taken = new Set<keyof T>();
  const pick = (list: readonly (keyof T)[]) => {
    const out: Record<PropertyKey, unknown> = {};
    for (const key of list) {
      if (!own.includes(key) || taken.has(key)) continue;
      taken.add(key);
      Object.defineProperty(out, key, { configurable: true, enumerable: true, get: () => props[key] });
    }
    return out;
  };
  const parts = keys.map(pick);
  parts.push(pick(own.filter((key) => !taken.has(key))));
  return parts as any;
}

// Adapted from solidjs/solid packages/web/src/client.ts style() (MIT, © 2016-2025 Ryan Carniato);
// setExtraStyles mirrors teact (MIT, © 2022 Alexander Zinchuk).
//
// Object form: per-property diff against the declarations this binding applied (held on the
// element), so imperative styles survive. String form: `cssText` replaces every declaration, so the
// extra styles set through `setExtraStyles` are kept in a per-element registry and re-applied after
// every cssText write (teact's `updateStyle` parity): a `<div style={props.style}>` whose
// `Transition`/`restoreHeight` sets `height` imperatively keeps that height across style updates.
// The binding's state lives on the element (the object it applied, or the string), so
// `style(el, null)`, string -> object transitions and a repeated identical string work without the
// caller's `prev` (spread calls pass it unreliably).
//
// Interactions: a property the object form drops is removed from the element even if `style:x` or
// `setExtraStyles` also set it; and the "unchanged" check compares with what the binding last wrote,
// not with the DOM, so an imperative overwrite of a bound property lives until the binding's value
// for it changes. Keep bound and imperative properties disjoint (the registry only guards against
// cssText, i.e. the string form).
//
// Names are CSS property names (kebab-case or `--custom`): `style={{ fontSize }}` is ignored by the
// CSSOM, as in Solid (DEV hint). `setExtraStyles` is the odd one out and takes camelCase (teact).
// A trailing `!important` in a value is passed as the priority; numbers get no `px`.

import { DEV } from '../env';

// string = the cssText this binding wrote; object = the declarations it applied.
const appliedStyles = new WeakMap<Element, string | Record<string, unknown>>();
// The extra styles in force per element (camelCase or `--custom` → value), re-applied after cssText writes.
// A Map, not a record: names come from data-driven objects and must not touch a prototype (own keys only, as above).
const extraStyles = new WeakMap<Element, Map<string, string | number>>();

type Styled = Element & { style: CSSStyleDeclaration };

const IMPORTANT = /\s*!important\s*$/i;
// Properties where a bare number is valid CSS.
const UNITLESS =
  /^(?:--|opacity$|z-index$|flex(?:-grow|-shrink)?$|order$|line-height$|font-weight$|zoom$|scale$|aspect-ratio$|columns?$|column-count$|orphans$|widows$|tab-size$|animation-iteration-count$|grid-(?:row|column|area)|.*-opacity$|stroke-(?:miterlimit|width|dashoffset)$)/;
const hinted = new Set<string>();

function hintOnce(key: string, message: string): void {
  if (hinted.has(key)) return;
  hinted.add(key);
  console.error(message);
}

function writeProperty(nodeStyle: CSSStyleDeclaration, name: string, value: unknown): void {
  if (DEV) {
    if (name.startsWith('--')) {
      if (typeof value === 'string' && value.includes(';')) {
        hintOnce(`;${name}`, `[frameact] style: the value of ${name} contains ";" — it can inject declarations when the style attribute is re-parsed.`);
      }
    } else if (!name.includes('-') && name !== name.toLowerCase()) {
      hintOnce(`c${name}`, `[frameact] style: "${name}" is not a CSS property name and is ignored; use the kebab-case "${name.replaceAll(/[A-Z]/g, (c) => `-${c.toLowerCase()}`)}" (only setExtraStyles takes camelCase).`);
    }
    if (typeof value === 'number' && value !== 0 && !UNITLESS.test(name)) {
      hintOnce(`n${name}`, `[frameact] style: "${name}: ${value}" is a number without a unit and is ignored; write "${value}px" or similar.`);
    }
  }
  const text = String(value);
  if (IMPORTANT.test(text)) nodeStyle.setProperty(name, text.replace(IMPORTANT, ''), 'important');
  else nodeStyle.setProperty(name, text);
}

function writeExtra(nodeStyle: CSSStyleDeclaration, name: string, v: string | number | null | undefined): void {
  if (name.startsWith('--')) {
    if (v == null) nodeStyle.removeProperty(name);
    else nodeStyle.setProperty(name, String(v));
  } else (nodeStyle as unknown as Record<string, string>)[name] = v == null ? '' : String(v);
}

/** `cssText = value`, then the element's extra styles on top (a cssText write drops every declaration). */
function writeCssText(node: Element, value: string): void {
  const nodeStyle = (node as Styled).style;
  nodeStyle.cssText = value;
  const extra = extraStyles.get(node);
  if (extra !== undefined) for (const [name, v] of extra) writeExtra(nodeStyle, name, v);
}

/** Compiler primitive for `style=`. */
export function style(node: Element, value: unknown, prev?: unknown): void {
  const nodeStyle = (node as Styled).style;
  const applied = appliedStyles.get(node);
  if (!value) {
    if (typeof applied === 'string' || typeof prev === 'string') writeCssText(node, '');
    if (applied !== undefined) {
      if (typeof applied === 'object') for (const name of Object.keys(applied)) nodeStyle.removeProperty(name);
      appliedStyles.delete(node);
    }
    return;
  }
  if (typeof value === 'string') {
    if (applied === value) return;
    writeCssText(node, value);
    appliedStyles.set(node, value);
    return;
  }
  const previous = typeof applied === 'object' ? applied : undefined;
  if (typeof applied === 'string' || typeof prev === 'string') writeCssText(node, '');
  const next: Record<string, unknown> = {};
  const obj = value as Record<string, unknown>;
  if (previous) {
    for (const name of Object.keys(previous)) if (!Object.hasOwn(obj, name) || obj[name] == null) nodeStyle.removeProperty(name);
  }
  for (const name of Object.keys(obj)) {
    const v = obj[name];
    if (v == null) continue;
    if (!previous || previous[name] !== v) writeProperty(nodeStyle, name, v);
    next[name] = v;
  }
  appliedStyles.set(node, next);
}

/** Compiler primitive for `style:name=` and inline style literals. */
export function setStyleProperty(node: Element, name: string, value: unknown): void {
  const nodeStyle = (node as Styled).style;
  if (value == null) nodeStyle.removeProperty(name);
  else writeProperty(nodeStyle, name, value);
}

/**
 * Imperative styles (teact API): camelCase properties are assigned, `--custom` ones set; null/undefined
 * removes. The declarations accumulate in a per-element registry (teact replaces the registry on
 * every call; here `setExtraStyles(el, { transition })` then `setExtraStyles(el, { height })` keeps
 * both) and are re-applied after every string `style=` write.
 */
export function setExtraStyles(el: Element, styles: Record<string, string | number | null | undefined>): void {
  const nodeStyle = (el as Styled).style;
  let extra = extraStyles.get(el);
  for (const name of Object.keys(styles)) {
    const v = styles[name];
    if (v == null) extra?.delete(name);
    else {
      if (extra === undefined) extraStyles.set(el, (extra = new Map()));
      extra.set(name, v);
    }
    writeExtra(nodeStyle, name, v);
  }
}

/**
 * Dev source lints. A scan over the JSX source, not a parser; the runtime cannot see these misuses.
 *
 * 1. `<input value={…}>` / `checked={…}` is written as a property by the compiler — only `use:value`
 *    controls it (spec §3.3). The scan walks the opening tag up to the first `>`, stepping over `=>`, so
 *    an arrow function in an earlier attribute (`onInput={e => …}`) does not end it. Literal values
 *    (`value={"x"}`, `checked={true}`, numbers, `null`) are skipped: the compiler inlines them into the
 *    template. Known false negative: a bare `>` in an earlier attribute expression
 *    (`disabled={n() > 1} value={v()}`) ends the scan early and the lint stays silent. Known false
 *    positive: a constant identifier (`value={LABEL}`) is not distinguished from a signal read.
 * 2. A static string event attribute on an intrinsic element (`<div onclick="…">`): the compiler inlines
 *    it into the template HTML, so the runtime's "no string handlers" check never sees it.
 * 3. Destructured props (trap no. 1 for a team coming from hooks): `function Chat({ isOpen })`,
 *    `const Chat = ({ isOpen }) =>`, `const Chat: FC<P> = function ({ … })` and, in a body,
 *    `const { isOpen } = props`. A component runs once, so a destructured prop is read once at creation
 *    and never updates. Only capitalised names are checked (a helper named `Format({ a })` is a
 *    known false positive; the message says so), and so is the body form inside a memo/effect compute,
 *    where the read is tracked and re-runs. A type annotation containing `=` or `=>` ends the declaration
 *    scan (known false negative). `props` is the conventional parameter name for the body form.
 */
const CONTROLLED_PROP =
  /<(input|textarea|select)\b(?:=>|[^>])*?\s(value|checked)=\{(?!\s*(?:"[^"]*"|'[^']*'|`[^`$]*`|-?\d[\d.]*|true|false|null|undefined)\s*\})/g;
const STRING_HANDLER = /<[a-z][\w-]*\b(?:=>|[^>])*?\s(on[A-Za-z]+)=["']/g;
const DESTRUCTURED_PARAM = /\b(?:function\s+([A-Z][\w$]*)\s*\(|(?:const|let|var)\s+([A-Z][\w$]*)\s*(?::[^=]*)?=\s*(?:function\s*\(|\())\s*\{/g;
const DESTRUCTURED_BODY = /\b(?:const|let|var)\s*\{[^}]*\}\s*=\s*props\b/g;

interface Lint {
  index: number;
  message: string;
}

function lintSource(code: string): Lint[] {
  const found: Lint[] = [];
  for (const match of code.matchAll(CONTROLLED_PROP)) {
    found.push({
      index: match.index,
      message: `<${match[1]} ${match[2]}={…}> is not controlled in frameact (the compiler writes the property directly). Use use:${match[2]}={accessor}.`,
    });
  }
  for (const match of code.matchAll(STRING_HANDLER)) {
    found.push({
      index: match.index,
      message: `${match[1]}="…" is a static string attribute: the compiler inlines it into the template HTML, bypassing the runtime's check. Use onClick={fn}-style handlers.`,
    });
  }
  for (const match of code.matchAll(DESTRUCTURED_PARAM)) {
    const name = match[1] ?? match[2];
    found.push({
      index: match.index,
      message: `<${name}> destructures its props: a component runs once, so a destructured prop is read at creation and never updates. Take \`props\` and read \`props.x\` where it is used (or splitProps). If ${name} is not a component, ignore this.`,
    });
  }
  for (const match of code.matchAll(DESTRUCTURED_BODY)) {
    found.push({
      index: match.index,
      message: 'const { … } = props reads the props once: the values never update. Read `props.x` where it is used (or splitProps).',
    });
  }
  return found;
}

/** Rollup position (1-based line, 0-based column) of a character index. */
function position(code: string, index: number) {
  let line = 1;
  let last = -1;
  for (let at = code.indexOf('\n'); at !== -1 && at < index; at = code.indexOf('\n', at + 1)) {
    line++;
    last = at;
  }
  return { line, column: index - last - 1 };
}

/**
 * Vite plugin: compile JSX/TSX with the Solid 2.0 compiler targeting `frameact/dom`. Client-side DOM
 * only: SSR is not supported in v1, and Vite's `ssr` transform flag is ignored (output is always DOM).
 */
export default function frameact(options: FrameactPluginOptions = {}): Plugin {
  const include = options.include ?? /\.[jt]sx$/;
  const exclude = options.exclude ?? /node_modules/;
  let dev = options.dev ?? true;
  return {
    name: 'frameact',
    enforce: 'pre',
    configResolved(config) {
      dev = options.dev ?? !config.isProduction;
    },
    async transform(code, id) {
      if (id.startsWith('\0')) return null;
      const file = id.split('?')[0];
      if (!include.test(file) || exclude.test(file)) return null;
      if (dev) {
        for (const lint of lintSource(code)) this.warn(lint.message, position(code, lint.index));
      }
      const result = await transformAsync(code, {
        filename: file,
        babelrc: false,
        configFile: false,
        sourceMaps: true,
        presets: file.endsWith('.tsx') ? [[typescript, {}]] : [],
        plugins: [[solid, compilerOptions(dev)]],
      });
      if (!result || result.code == null) return null;
      return { code: result.code, map: result.map as any };
    },
  };
}

How it works (read before writing): the alive keys are a signal (`[active]` at creation; on a key change `{previous, active}`, or every visited key with `renderCount`; `shouldCleanup` after an animation keeps `{active}` + `cleanupExceptionKey`, or drops `cleanupOnlyKey`). A `Slides` component provides `scope` and renders `<For each={alive} keyed order="manual">` — each row is a `div.Transition_slide` registered in a `Map<key, element>` and holding the slide content created once. The keys effect is created before the animate effect, so it runs first in a drain; the animate effect's **compute pulls `rows()`**, which creates the new key's slide before its apply; its apply (mutate phase) sets `-from`/`-to`/`-inactive`, begins the heavy animation on `scope`, toggles the container's `Transition-${name}[Backwards]` class and waits for the watched slide's `animationend`; the handler does the writes in `requestMutation`: classes back to `-active`/`-inactive`, `settledKey` (restoreHeight), `onStop`, `end()`, then the cleanup policy (a signal write; the slide removal lands in the following frame). An older step's handler that finds `currentKey` changed only calls its `end()`. A switch without animation sets the classes and `settledKey` at once. `restoreHeight` is a forced-reflow effect on `settledKey`/`restoreHeightKey`/`contentSelector` (it runs after the mutate phase that created and attached the slide) handing `{ key, height }` to a mutation effect — same frame. Disposal cancels the waits, ends every pending heavy animation and turns an already-booked end task into a no-op.

/**
 * A fake vertical layout for jsdom (which lays nothing out): every `.ListItem` child of `list` is
 * `itemHeight` px tall and stacked in DOM order; the scroller has a writable `scrollTop`, a viewport
 * of `viewport` px and a `scrollHeight` of (items × itemHeight). Item rects are relative to the
 * scroller's scroll position, so a prepend moves the old first item's `top` down by the new rows.
 */
export function fakeLayout(scroller: HTMLElement, list: HTMLElement = scroller, itemHeight = 40, viewport = 200, onWrite?: (top: number) => void): void {
  let scrollTop = 0;
  const items = () => Array.from(list.querySelectorAll<HTMLElement>('.ListItem'));
  Object.defineProperty(scroller, 'scrollTop', {
    configurable: true,
    get: () => scrollTop,
    set: (v: number) => {
      scrollTop = Math.max(0, v);
      onWrite?.(v);
    },
  });
  Object.defineProperty(scroller, 'scrollHeight', { configurable: true, get: () => items().length * itemHeight });
  Object.defineProperty(scroller, 'clientHeight', { configurable: true, get: () => viewport });
  Object.defineProperty(scroller, 'offsetHeight', { configurable: true, get: () => viewport });
  const origin = () => ({ top: -scrollTop, left: 0, width: 300, height: viewport, right: 300, bottom: viewport - scrollTop, x: 0, y: -scrollTop, toJSON: () => ({}) });
  scroller.getBoundingClientRect = () => ({ ...origin(), top: 0, y: 0 }) as DOMRect;
  const proto = Object.getPrototypeOf(scroller) as HTMLElement;
  // Items are measured through the prototype getters we override here (per element would miss new rows).
  Object.defineProperty(proto, 'offsetTop', { configurable: true, get(this: HTMLElement) { return items().indexOf(this) * itemHeight; } });
  Object.defineProperty(proto, 'offsetHeight', { configurable: true, get(this: HTMLElement) { return this === scroller ? viewport : itemHeight; } });
  Object.defineProperty(proto, 'offsetParent', { configurable: true, get(this: HTMLElement) { return this.isConnected ? scroller : null; } });
  proto.getBoundingClientRect = function (this: HTMLElement) {
    if (this === scroller) return { ...origin(), top: 0, y: 0 } as DOMRect;
    const top = items().indexOf(this) * itemHeight - scrollTop;
    return { top, bottom: top + itemHeight, left: 0, right: 300, width: 300, height: itemHeight, x: 0, y: top, toJSON: () => ({}) } as DOMRect;
  };
}

/** Undo `fakeLayout`'s prototype overrides (call in afterEach). */
export function resetLayout(): void {
  const proto = HTMLElement.prototype as unknown as Record<string, unknown>;
  delete proto.offsetTop;
  delete proto.offsetHeight;
  delete proto.offsetParent;
  delete (proto as { getBoundingClientRect?: unknown }).getBoundingClientRect;
}

```ts
// Scroll anchoring across a list update (telegram-tt `InfiniteScroll`'s "restore scrollTop after
// adding items", `MessageList`'s useSyncEffect + forceMeasure snapshot), phase-correct on frameact:
//   1. a MEASURE effect on `items` runs in the frame the list changes, before the mutate drain updates
//      the DOM: it snapshots the anchor item and its position (the "before");
//   2. a FORCED-REFLOW effect on the same `items` runs after the mutate drain of that frame: it reads
//      the anchor's new position and writes the corrected scrollTop through a signal, which a mutation
//      effect applies in the forced-reflow mutate phase of the SAME frame (no flash of the wrong offset).
// Under heavy-animation parking the three effects park together and are released in one frame in
// phase order (the store-gate release goes through a measure task — audit R1): create the anchor under
// the same heavy-animation scope as the list it anchors, so that they park and release together.
import { createEffect, createMeasureEffect, createMutationEffect, createSignal, frameForcedReflow, untrack, type Accessor } from '../index';
import { TRACK } from '../core/symbols';

/**
 * What a list change is detected by: a store array (model B: `produce`/`reconcile` rewrite it in
 * place, its identity never changes) through its shape — `[$TRACK]` subscribes to the shape only and
 * returns a fresh plain array per change — anything else by its own identity.
 */
export function trackItems(value: unknown): unknown {
  if (value !== null && typeof value === 'object') {
    const shape = (value as { [TRACK]?: unknown })[TRACK];
    if (shape !== undefined) return shape;
  }
  return value;
}

export interface ScrollAnchorOptions {
  /** The element whose `scrollTop` is kept (and, unless `list` is given, the one holding the items). */
  container: Accessor<HTMLElement | null | undefined>;
  /** The element holding the items when it is not the scroll container (a nested list). */
  list?: Accessor<HTMLElement | null | undefined>;
  /** Tracked: every change snapshots before and restores after the DOM update (a store array by its shape). */
  items: Accessor<unknown>;
  /** Default `.ListItem`. */
  itemSelector?: string;
  /** Skip the restore (frequently re-ordered lists). */
  noScrollRestore?: Accessor<boolean | undefined>;
  /** Skip the restore while the container is scrolled to the top (a chat list: new chats push the rest down). */
  noScrollRestoreOnTop?: Accessor<boolean | undefined>;
}

export interface ScrollAnchor {
  /** The item the position is kept relative to (the first item, until `track` chose another). */
  anchor: () => HTMLElement | undefined;
  /** The anchor's remembered `getBoundingClientRect().top`. */
  anchorTop: () => number;
  /** From a scroll handler: make `el` the anchor and remember its position (`top` = its `getBoundingClientRect().top`). */
  track(el: HTMLElement | undefined, top?: number): void;
  /** The item elements as of the last snapshot/restore (a live query is avoided in scroll handlers). */
  items(): HTMLElement[];
  /** True once, right after a restore wrote `scrollTop`: the scroll event it causes is not the user's. */
  consumeRestored(): boolean;
}

const DEFAULT_ITEM_SELECTOR = '.ListItem';

export function createScrollAnchor(options: ScrollAnchorOptions): ScrollAnchor {
  const { container, items, noScrollRestore, noScrollRestoreOnTop } = options;
  const list = options.list ?? container;
  const selector = options.itemSelector ?? DEFAULT_ITEM_SELECTOR;
  let anchor: HTMLElement | undefined;
  let anchorTop = 0;
  let elements: HTMLElement[] = [];
  let restored = false;
  const [scrollTopFix, setScrollTopFix] = createSignal<{ top: number } | undefined>(undefined);

  function query(): HTMLElement[] {
    const root = untrack(list);
    elements = root ? Array.from(root.querySelectorAll<HTMLElement>(selector)) : [];
    return elements;
  }

  const tracked = () => trackItems(items());

  // 1. Before the update (measure phase of the frame the items change).
  createMeasureEffect(
    tracked,
    () => {
      const current = query();
      if (anchor === undefined || !current.includes(anchor)) anchor = current[0];
      if (anchor) anchorTop = anchor.getBoundingClientRect().top;
    },
    { name: 'scrollAnchor.snapshot' },
  );

  // 2. After the update (forced-reflow phase of the same frame).
  createEffect(
    tracked,
    () => {
      const el = untrack(container);
      const current = query();
      if (!el) return;
      if (anchor !== undefined && current.includes(anchor)) {
        const newTop = anchor.getBoundingClientRect().top;
        const delta = newTop - anchorTop;
        anchorTop = newTop;
        if (delta !== 0 && !untrack(() => noScrollRestore?.()) && !(untrack(() => noScrollRestoreOnTop?.()) && el.scrollTop === 0)) {
          setScrollTopFix({ top: el.scrollTop + delta });
          anchorTop -= delta; // after the write the anchor is back where it was
        }
      } else {
        anchor = current[0];
        if (anchor) anchorTop = anchor.getBoundingClientRect().top;
      }
    },
    frameForcedReflow,
    { name: 'scrollAnchor.restore' },
  );

  // 3. The write (forced-reflow mutate phase of the same frame).
  createMutationEffect(
    () => scrollTopFix(),
    (fix) => {
      const el = untrack(container);
      if (fix === undefined || !el) return;
      el.scrollTop = fix.top;
      restored = true;
    },
    { name: 'scrollAnchor.write' },
  );

  return {
    anchor: () => anchor,
    anchorTop: () => anchorTop,
    track(el, top) {
      anchor = el;
      if (el) anchorTop = top ?? el.getBoundingClientRect().top;
    },
    items: () => elements,
    consumeRestored() {
      const was = restored;
      restored = false;
      return was;
    },
  };
}
```

## 2. The traps (read these twice)

1. **Destructuring props.** `function Chat({ isOpen })` reads `isOpen` once, at creation; it never updates.
   Take `props` and read `props.isOpen` where it is used — in JSX, inside a memo, inside an effect's
   compute. The Vite plugin warns on `function X({`, `const X = ({`, and `const { a } = props` in dev.
   To forward a subset use `splitProps(props, ['a', 'b'])` (lazy getters) or `mergeProps`.
2. **Reading a prop or a signal early.** `const open = props.isOpen;` at the top of the component is the same
   trap without braces. So is `const chat = state.chats[id]` followed by `chat.title` in JSX — that one is
   fine (the proxy is read lazily), but `const title = state.chats[id].title` is a one-time read.
3. **Handler props are bound once.** `<button onClick={props.onClick}>` attaches the function it sees at
   creation. If the parent can replace the handler, write `onClick={(e) => props.onClick?.(e)}`.
4. **No `useLastCallback`.** Delete it. A handler defined in the component body sees the current signal
   values because it calls accessors.
5. **Effects: side effects in `apply`, never in `compute`.** `createEffect(() => state.draft, (draft) => save(draft))`.
   A DOM write in `compute` runs in the wrong phase and under tracking.
6. **Measure in measure, mutate in mutate.** Layout reads (`getBoundingClientRect`, `offsetHeight`,
   `scrollTop` read, `focus()`) belong in `createMeasureEffect`, `onMount`, an event handler or a
   `requestMeasure` task; DOM writes in `createMutationEffect` or `requestMutation`. Need a read after a
   write in the same frame? `createEffect(c, a, frameForcedReflow)` or `requestForcedReflow`.
7. **`onCleanup` in an apply is a DEV error.** Return the cleanup from `apply` instead. In the component
   body, `onDestroy(fn)` (or `onCleanup`) runs at disposal, synchronously — a live-DOM write there (a class
   on `document.body`) goes through `requestMutation`.
8. **Identity memos go stale under in-place writes** (audit R2, see §5.3).

## 4. The frame: phases and scroll anchoring

A frame runs **measure → mutate → forced reflow**; every phase drains its queue of effect runs once.
A signal written in a measure apply reaches a mutation effect in the same frame; one written in a
mutate apply reaches a measure effect only next frame (DEV warns). The idiom teact spells as
`useSyncEffect + forceMeasure` (snapshot) + `useLayoutEffect + requestForcedReflow` (restore) is:

```ts
createMeasureEffect(() => props.items, () => { top = anchor.getBoundingClientRect().top; });  // before the DOM update
createEffect(() => props.items, () => { setFix(scrollTop + (anchor.getBoundingClientRect().top - top)); }, frameForcedReflow); // after it
createMutationEffect(() => fix(), (v) => { if (v !== undefined) el.scrollTop = v; });        // forced-reflow mutate phase, same frame
```

That is `createScrollAnchor` in `frameact/kit`. Under a heavy animation all three park and are released
together, measure first (the store-gate release goes through a measure task for this — audit R1, fixed in the store's fix round).
Create the anchor under the same heavy-animation scope as its list. A store array is tracked by its shape, so
`produce`/`reconcile` writes in place are anchored too.

## 5. The store model (model B) for the client

### 5.1 Writes

- **A value at a path replaces**: `setState('chats', id, chat)`. **`merge()` merges** one level:
  `setState('chats', id, merge({ title, unreadCount }))`. **`undefined` deletes** the key:
  `setState('chats', id, undefined)`. Arrays: `produce((a) => a.splice(i, 1))`, never a hole.
- **Server chunks**: `setState('messages', chatId, reconcile(chunk))` — matched by `id`, rows keep
  their identity, only changed leaves notify. Use it for everything that arrives as immutable objects.
- **Drafts and multi-field updates**: `produce((draft) => { … })`.
- **Never write from a render**: writes belong in actions (`defineActions`) or event handlers.
  A nested action call is queued (FIFO), `afterActions(cb)` runs after the cascade.
- Reducers that return `{ ...global, … }` become path writes. Keep the *selectors* — pure functions over
  the proxy track themselves; put a derived array in a `createMemo`.

### 5.2 Reads

- In JSX and effects: read the proxy (`state.chats[id].title`). Each read is one leaf subscription.
- In handlers and actions: read the proxy too (untracked outside computations), or `unwrap(state.chats)`
  for a raw object to hand to a worker. `structuredClone(proxy)` throws — `snapshot()` (O(n)) or
  `unwrap` first.
- `byTabId`: keep tab state under `state.byTabId[tabId]`; a selector `selectTabState(state, tabId)` is a
  plain function, call it in JSX.
- Lists: `<For each={state.messages[chatId]}>` subscribes to the array's shape; an edited message wakes
  its row only.

### 5.3 Identity pitfalls (R2)

In teact, `global.chats.byId` is a new object after every change, so `useMemo(..., [chatsById])` and
`memoized(selector)` by argument identity are correct. In model B the **same object is mutated in
place**: an identity-keyed memo returns the stale result forever. Port every such memo to
`createMemo(() => …)` (it tracks the leaves it reads) and delete `util/memoized.ts`-style caches over
store objects. The same holds for `shallowEqual` guards: compare values, not references, or just let
the leaf subscriptions do their job.

### 5.4 Animations

Store-caused frame effects inside an animating scope park until the animation ends; local signals,
events, `live()` reads and `ungated()` writes do not wait. tickEnd logic is never parked. A
`<Transition>` creates a scope per subtree (pass `scope` to share one), so the chat list keeps
updating while the right column slides. View Transitions and the iOS back gesture: write through
`ungated(() => setState(…))` and commit with `flushSync()` (contract to be fixed in plan 4).

### 5.5 Cache and multitab

There is no change feed yet (follow-up: `onStoreWrite` / a patch journal). For a cache, serialise a
subset of `unwrap(state)` in `onFullyIdle` / `createIdleEffect`, throttled; the per-write
`addCallback` + `deepDiff` of tt is not expressible until the feed lands.

## 6. Idioms, short

- `isOpen && <X/>` → `<Show when={isOpen()}><X/></Show>`; keyed remount → `<Show when={id()} keyed>`.
- `lang('Key')` is reactive when `lang` reads the language signal; `withNodes` arrays replace whole:
  render rich text with `<For>` keyed by entity so `CustomEmoji`/lottie nodes survive text edits.
- `requestMeasure(() => el.focus())` in an action; in a component `onMount(() => el.focus())`.
- `beginHeavyAnimation(…, true)` freezes every frame queue globally; prefer a scope (`createHeavyAnimationScope`,
  `<HeavyAnimationScope>`, `<Transition scope>`) so only the moving subtree waits.
- `flushSync()` is for tests and imperative glue (View Transitions, iOS gesture) only.
