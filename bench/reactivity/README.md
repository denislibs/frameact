# Бенчмарк реактивного графа

frameact в [js-reactivity-benchmark](https://github.com/transitive-bullshit/js-reactivity-benchmark)
(коммит `2c273f164cea0d7eae9d383f4b9ab699e550109d`) рядом с Solid, Preact Signals, Alien Signals,
Vue, Svelte, Angular, MobX и др. Без форка: апстрим клонируется локально и патчится.

## Что измеряется

Только слой реактивного графа в Node.js: создание сигналов/мемо/эффектов, распространение
изменений (kairo: diamond, deep, broad, mux…; $mol; S.js; динамические графы; CellX). Все результаты
проверяются на корректность (значения и, для frameact, число пересчётов — `testPullCounts: true`).

**Не измеряется:** DOM, фазы кадра (measure/mutate), `mapArray`, рендеринг, память, реальные
приложения. Эти графы — мелкие примитивы; итог не равен скорости UI.

## Запуск

```sh
pnpm bench:reactivity                 # проверки + полный прогон (~10 мин) → results/
node bench/reactivity/run.mjs --check # только проверки + smoke frameact
node bench/reactivity/run.mjs -- --framework frameact,solid,preact --suite kairo
```

Нужны git, pnpm и Node ≥ 22.12. `run.mjs` клонирует апстрим в `.upstream/` (в .gitignore),
сбрасывает его к закреплённому коммиту, применяет `upstream.patch` (регистрация адаптера в
`config.ts`/`registry.ts` и зависимость `frameact: link:../../..`), копирует `adapter.ts`, ставит
зависимости ровно по lockfile апстрима, гоняет его тесты адаптеров, typecheck, сборку, CLI-проверки,
smoke frameact и затем бенчмарк. Отчёт копируется в `results/latest.{json,csv,md}` + `latest.svg`.

## Адаптер (`adapter.ts`)

- Публичный API: `createSignal` / `createMemo` / `createEffect` / `createRoot` — меряем то, что
  платит приложение (включая обёртки-аксессоры над узлами maverick).
- `effect(fn)` = `createEffect(fn, noop)`: работа в отслеживаемой `compute`-половине
  (она выполняется синхронно при создании), `apply` пустой. Планировщик — стандартный `tickEnd`,
  как в приложении.
- `withBatch`/`withBuild` на внешней границе вызывают `flushSync()`, который синхронно сливает
  очередь `tickEnd`, так что к возврату эффекты уже отработали. Защита `tickEnd` от циклов считает
  запуски эффекта за один прогон очереди, а каждый `flushSync()` — отдельный прогон, поэтому тысячи
  синхронных обновлений бенчмарка за циклы не принимаются.
- `withBatch` — только точка слива: запись в frameact никогда не запускает эффекты синхронно,
  отдельного `batch` нет.
- `withBuild` — `createRoot` (detached); `dispose` регистрируется в `retain()` апстрима и
  вызывается после нагрузки, вне измерений.

## Как читать результаты

`results/latest.md`, таблица «Comparison by workload family»: геометрическое среднее отношений
времени движка к самому быстрому на каждом кейсе; 1× — быстрейший везде, меньше — лучше. Общего
балла нет. Значения — минимум из 3 замеров в мс, каждый фреймворк/сьют — в отдельном процессе.
`latest.svg` ранжирует по среднему арифметическому всех замеров (доминируют тяжёлые кейсы).

Снимок в `results/` снят на: Apple M1 Pro, 16 ГБ, macOS 26.5, Node v24.3.0, frameact на `main`
(5f5eede). Сравнивать с цифрами из README апстрима (M3 Pro, Node 25) нельзя — только внутри одного
прогона.

## Снимок (2026-10-12, эффекты на `tickEnd`)

Все 5 сьютов frameact прошли (34 кейса, 0 ошибок; тесты адаптера — включая точное число
пересчётов). Геосреднее отношения к быстрейшему (меньше — лучше):

| Движок | kairo | mol | s | dynamic | cellx |
| --- | ---: | ---: | ---: | ---: | ---: |
| alien-signals | 1.02× | 1.25× | 1.02× | 1.00× | 1.00× |
| Preact Signals | 1.21× | 1.25× | 1.24× | 1.29× | 2.75× |
| @vue/reactivity | 2.01× | 1.25× | 1.45× | 1.65× | 2.41× |
| **frameact** | 3.04× | 1.27× | 2.95× | 2.08× | 2.40× |
| SolidJS | 3.84× | 1.52× | 2.73× | 3.42× | 1.81× |

- По сравнению с прошлым снимком (своя очередь эффектов в адаптере: 2.68 / 1.31 / 2.89 / 1.97 /
  2.69) путь `tickEnd` + `flushSync()` добавляет ≈0.35× на kairo — это реальная цена планировщика
  приложения и отдельная цель оптимизации.
- Обновления (kairo, s/update*, dynamic) — 1.5–3.8× от alien, на уровне Vue и быстрее Solid 1.x.
- Слабое место — создание: `s/createComputations{1,2,4}to1` 6–9× от alien. Профиль: ~30% GC.
  Гипотеза: аллокации на узел — `read.bind`/`write.bind` maverick, обёртки-аксессоры
  `createSignal`/`createMemo`, объект опций `{ id, dirty: toDirty() }` на каждый сигнал, массивы
  `_sources`/`_observers`, плюс добавление каждого узла в `_children` владельца.
- cellx — микросекундные времена, шум.
